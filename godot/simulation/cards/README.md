# Card balance laboratory

The playable Older Brother deck now starts at **12 cards**, with a fixed-size
**five-card opening** and discoveries shuffled in. This is a human-playtest
baseline, not a new simulator-selected balance. The earlier
[shuffled-discovery experiment](SHUFFLED_FINDINGS.md) and
[guaranteed-opening study](PROGRESSION_FINDINGS.md) used larger decks; their win
rates do not describe this version.

Run real matches without graphics or audio, compare controlled tuning experiments,
and inspect where cards or rules stop creating interesting decisions. The
simulation uses `match_rules.gd`, `match_combat.gd`, and `match_ai.gd` directly.
No separate Python implementation of the game determines the results.

From the repository root:

```sh
python3 tools/card_sim.py
```

This runs the scenarios in `experiments.json` with 200 shared seeds per policy.
Godot is discovered from `GODOT`, `PATH`, `/Applications`, or this workspace's
downloaded runtime. To specify it:

```sh
GODOT=/path/to/Godot python3 tools/card_sim.py --seeds 500
```

Outputs go to ignored `godot/build/web/balance/`. With the normal game server
running, open **http://localhost:8060/balance/report.html**. The report also works
directly as a local HTML file; its charts and filters need no internet or packages.
There is no new server, native game window, or audio playback.

## What is measured

- Wins, losses, and turn-cap timeouts are distinct outcomes. Win-rate confidence
  intervals describe resolved bot matches, not human success rates.
- Round distributions, lead changes, comeback wins, fatigue, and blocked enemy
  deployments expose pacing and structural problems.
- Unspent Attention, full boards, hand overflow, and turns starting with no legal
  actions indicate constrained decisions. A legal move can still be strategically
  worthless; the metric does not prove that a turn was interesting.
- Card draws, plays, held turns, and turns with a legal target expose unused cards.
  Drawing a card is not evidence that playing it would help. Per-card usage is
  descriptive, not a causal estimate of that card's power.
- Creature lifespan and hits received are split between creatures that died and
  those still alive when the game ended. Survivors are **censored** observations;
  they must not be counted as creatures that died after one turn.
- Interceptions, intercepted attack damage, swaps, damage spells, and healing show
  whether the mechanics actually occur.

The downloadable `results.json` retains per-match counters, card and creature
records, and compact turn timelines. CSVs support spreadsheet analysis. The report
compares each variant with its named baseline using the same seed and policy,
including gained/lost wins and a paired bootstrap interval. Seed pairing reduces
noise; it does not make bot heuristics representative of human players.

## Players and information boundaries

The standard suite includes `random`, `aggressive`, `defensive`, and `tactical`.
`passive` is also available as a negative control that only ends turns.

All policies receive a whitelisted public observation, their own hand, and legal
actions generated by the real rules. They can see the incoming **lane**, never the
hidden card, shuffled deck order, or enemy reserve order. Policy randomness has a
separate seeded generator, so it cannot alter the deck shuffle.

Tactical evaluates each candidate's immediate visible combat using the production
combat resolver. It does not search future draws or predict the hidden deployment.
It is a useful stronger heuristic, **not an optimal solver**. Aggressive and
defensive deliberately emphasize different values. Their disagreement is useful
evidence of a design question, not proof that one style is universally superior.

## Change one thing, then compare

Edit or copy `experiments.json`; the shipped encounter defaults stay unchanged.
An experiment has a unique ID, a readable label, an opponent, optional baseline
ID, and match-local overrides:

```json
{
  "scenarios": [
    {"id": "baseline", "opponent": "older_brother", "overrides": {}},
    {"id": "tougher_veteran", "opponent": "older_brother", "baseline": "baseline",
     "overrides": {"enemy_cards": {"veteran": {"power": 4}}}},
    {"id": "no_player_intercept", "opponent": "older_brother", "baseline": "baseline",
     "overrides": {"player_cards": {"sentinel": {"ability": ""}}}}
  ]
}
```

Supported encounter overrides: `goal`, `lanes` (3 or 4), `starting_attention`,
`attention_cap`, `opening_hand`, `fixed_opening`, `deck`, `reserve`, `opening_lanes` (zero-based), and
`collected_cards` for the older brother's real discovery progression.
The tutorial uses an infinite repeating enemy sequence, so reserve and opening
board experiments require Older Brother. The older opening keeps three core
creatures fixed, shuffles the remainder, then draws two more cards. The tutorial
keeps all four opening cards fixed. Seeds therefore vary the older random
opening slots and follow-up draws, but never the guaranteed core creatures.
`fixed_opening` is the number dealt from the deck prefix before shuffling and
must be between zero and `opening_hand`. The remaining opening slots draw from
the shuffled pile. Older defaults are three fixed out of five; tutorial defaults
are four fixed out of four. Live Older Brother visits start with a fresh random
seed, while simulation runs remain explicitly seeded and reproducible.

`cards` changes both sides, `player_cards` changes only the player, and
`enemy_cards` changes only the opponent. Side-specific overrides take precedence.
Creature tuning supports `cost`, `power`, `health`, and `ability` (`""`,
`intercept`, `diagonal`, `heal_allies`). Damage and healing spells support `cost`
and `amount`, including the stronger collectible spells.
The enemy does not spend Attention, so its card cost does not price deployments;
cost can affect the tutorial's existing sequence substitution. Invalid fields,
IDs, decks, stats, and lane indices are rejected instead of silently ignored.

Changing Forkshot's ability to `""` makes it attack straight ahead; it is a
straight-attack replacement experiment, not removal of all its attacks.
Removing Sentinel's ability preserves its health, cost, zero power, and deck slot.
Those are controlled tests of the abilities, unlike removing cards from the deck
and inadvertently improving draw consistency at the same time.

```sh
python3 tools/card_sim.py --config /path/to/experiments.json --seeds 500
python3 tools/card_sim.py --scenarios older_baseline --policies tactical --seeds 50
python3 tools/card_sim.py --trace older_baseline:tactical:17
```

Trace runs default to a separate `balance/replay/` directory so they preserve the
main report. A trace records actual actions and authoritative event snapshots for
one match. Hidden incoming card identities are removed from the saved snapshots;
bots never receive the trace. The report provides replay commands for individual seeds.
Use `--output /path/to/run` to keep multiple named experiments.

Each run records its complete experiment input, resolved settings, source hashes,
Godot version, Git revision/dirty status, seeds, and command. Reproducing old
results requires the same rules and policy source, not just the same seed. The
saved report data is useful even after the source evolves.

## Measure the collection curve

The previous 25,600-match guaranteed-opening study and diagnosed policy
limitations are recorded in [the historical progression findings](PROGRESSION_FINDINGS.md).
Use the bundled `progression.json` for all 32 discovery subsets under the current
live rules. Re-running it now measures the smaller shuffled deck, not that study.

The playable older encounter always opens with five cards: Bruiser, Forkshot,
Sentinel, and two random draws from the shuffled remainder. With `k` collected
cards, the deck has `12 + k` cards and the remaining draw pile has `7 + k`.
Discoveries are added once and shuffled normally; they can appear in either
random opening slot or in later draws. The hand limit is eight. Added cards can
change draw order and delay fatigue, so paired seeds no longer imply an identical
base-card tail. The hall and simulator share this same dealing contract.

Use `collected_cards` to model a real collection, instead of manually constructing
deck prefixes and opening sizes:

```json
{
  "scenarios": [
    {"id": "no_discoveries", "opponent": "older_brother",
     "overrides": {"collected_cards": []}},
    {"id": "champion_found", "opponent": "older_brother", "baseline": "no_discoveries",
     "overrides": {"collected_cards": ["champion"]}},
    {"id": "all_found", "opponent": "older_brother", "baseline": "no_discoveries",
     "overrides": {"collected_cards": ["champion", "aegis", "tempest", "renewal", "thunderbolt"]}}
  ]
}
```

`collected_cards` is available only for Older Brother. IDs must be unique members
of the five-card collection; it cannot be combined with custom `deck` or
`opening_hand` or `fixed_opening` settings. `deck_progression.gd` adds discoveries while keeping
base-card multiplicity intact. Discovery order does not change the resulting
deck; each unique subset has one canonical layout.

For a full study, include **all 32 subsets** with the same opponent/card tuning
and seed range. There are 80 possible single-card additions between those subsets.
Testing only one five-card acquisition order can conceal an upgrade that weakens
another hand or a particularly weak subset. Use a separate seed range to validate
a candidate selected during tuning.

```sh
python3 tools/card_sim.py --config godot/simulation/cards/progression.json --seed-start 10000 --seeds 200 --output godot/build/web/progression-current
python3 tools/card_progression_report.py godot/build/web/progression-current/results.json
```

The second command writes `curve.html` and `progression-summary.json` beside the
regular report. With the local server running, open
**http://localhost:8060/progression-current/curve.html**. Using a new output directory
preserves the older measured reports. It groups results by collection
size, shows weakest/strongest subsets, and compares each single-card addition
using paired seeds. Incomplete subset or seed coverage stays explicit. These are
bot-based diagnostics rather than a guaranteed human difficulty curve.

The dated `FINDINGS.md`, `PROGRESSION_FINDINGS.md`, and `SHUFFLED_FINDINGS.md`
describe earlier configurations. Preserve them as historical evidence; their
numbers must not be presented as current win rates. The current small-deck
iteration is awaiting human playtesting rather than another automated balance sweep.

## Modules and verification

- `run.gd`: strict CLI/configuration parsing, seeded real matches, optional traces.
- `metrics.gd`: observational event telemetry and creature tracking.
- `policies.gd`: legal action enumeration and public-information policies.
- `public_preview.gd`: visible-board evaluation for heuristics; it shares combat.
- `../../minigames/cards/match_config.gd`: validated, isolated match tuning.
- `../../../tools/card_sim.py` (repository root): background execution, provenance,
  report workflow.
- `tools/card_sim_report.py` and `.html`: aggregation and offline report.
- `tools/card_progression_report.py` and `.html`: collection curve and subset-edge
  comparisons, with shared-seed uncertainty rather than independent-subset claims.

Run the simulation tests documented in `godot/tests/README.md`, plus the existing
little/older rules suites when changing the resolver. Run paired baseline seeds
before interpreting a tuning change. Human playtesting is still necessary for
readability, bluffing, satisfaction, and whether the decisions feel meaningful.
